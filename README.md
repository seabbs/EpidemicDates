An interactive page exploring onset-date imputation for cases with a missing onset.
Each missing onset is set to the report date minus a delay drawn from the pooled empirical onset-to-report delays.
This is the approach discussed in [BDBV-Modeling-Hub issue #61](https://github.com/InsightNet-US/BDBV-Modeling-Hub/issues/61).

**Live page:** <https://seabbs.github.io/epidemic-imputation-demonstration/>

The page simulates an epidemic with time-varying growth, reporting delays, missing onset dates and changing ascertainment.
It compares four ways of imputing missing onsets against the true onsets of the same cases:

| Key | Method |
|---|---|
| `hub` | Draw a delay from the pooled empirical delays of cases with both dates |
| `mean` | Shift by the rounded mean empirical delay |
| `fwd` | Draw a delay from the forward delay distribution |
| `gen` | EM back-projection, a partial deconvolution of the missing-onset cases |

Growth rate and ascertainment can be drawn directly on the page.
Presets use Ebola settings from [epiforecasts/BVDOutbreakSize](https://github.com/epiforecasts/BVDOutbreakSize) and [epiforecasts/bdbv-linelist-analysis](https://github.com/epiforecasts/bdbv-linelist-analysis).

## Using the JavaScript module

`imputation.js` has no dependencies.
In a browser it defines a global `Imputation`.
In Node load it with `require`:

```js
const Imputation = require("./imputation.js");

// growth rate r(t) per day, linear between points every 15 days
const knots = Imputation.knotsFrom([[0, 0.05], [60, 0.05], [120, -0.01]]);

const res = Imputation.run({
  knots,
  mu0: 8, mu1: 8, cv: 1,   // mean onset-to-report delay (days) at start and end, and its CV
  pi0: 0.4, pi1: 0.4,      // fraction of onsets missing at start and end
  retro: true              // false to cut the data at `cutoff`
});

res.truth;             // weekly true onsets of cases reported by the cut-off
res.imputed.hub;       // weekly onsets after imputation, by method (hub, mean, fwd, gen)
res.rt.hub;            // weekly Rt from the imputed counts
res.metrics.hub;       // maxRel, meanAbs, maxR, wrongSide, peakShift, peakHeight, last
```

`Imputation.DEFAULTS` lists every parameter and `Imputation.PRESETS` holds the page's scenarios.
Lower-level pieces are also exported: `scenario`, `expectedData`, `runMethods`, `stochastic`, `delayPmf`, `growth` and `rToR`.

Delays are double interval censored daily Gamma pmfs (the primarycensored form with a uniform primary event).
Rt uses a Gamma generation interval with mean 15 days and SD 9.

## Using the Python simulation

The simulation is a package, `imputation_sim`, managed with [uv](https://docs.astral.sh/uv/).

```bash
uv run imputation-sim --reps 200 --out output          # all scenarios
uv run imputation-sim --reps 50 --scenarios C D W       # a subset
```

From Python:

```python
import imputation_sim as sim

sim.DESC                                   # scenario descriptions
rows = sim.run_scenario("W", reps=100)    # summary rows per cut-off and method
sim.write_results(rows, "output")
```

## Using it on a real line list

Both languages have a function that takes a line list and returns daily onset counts under each method.
You need one row per case with:

- a **report day** for every case;
- an **onset day** where known, and empty where it is missing.

Days must be whole numbers, for example days since the first report.
Set the cut-off to the last report day in your data vintage.
Cases with an onset after their report, or a delay longer than the maximum, are dropped and counted in `dropped`.

In Python (pandas shown for reading the data):

```python
import pandas as pd
import imputation_sim as sim

ll = pd.read_csv("linelist.csv", parse_dates=["onset_date", "report_date"])
day0 = ll["report_date"].min()
onset = (ll["onset_date"] - day0).dt.days        # NaN where onset is missing
report = (ll["report_date"] - day0).dt.days

res = sim.impute_linelist(onset, report, cutoff=report.max())
res["imputed"]["hub"]    # back-sampling from pooled empirical delays
res["imputed"]["em"]     # EM back-projection with an estimated delay
res["empirical_delay"]   # pooled delay pmf from cases with both dates
```

In JavaScript:

```js
const { imputeLinelist } = require("./imputation.js");

const res = imputeLinelist({
  onset: [0, 2, null, 5, null],   // null where onset is missing
  report: [3, 6, 7, 9, 12],
  cutoff: 12,
  delay: null                     // or a forward delay pmf to hold fixed
});
res.imputed.hub;   // daily onset counts, hub method
res.imputed.gen;   // daily onset counts, EM back-projection
res.generativeDelay;
```

Day `i` of each output is onset day `i`.
Sum to weeks before comparing methods or estimating growth.
Outputs are expected allocations, not random draws, so they are not whole numbers.

Things to check before relying on the output:

- **Missingness.** All methods assume onsets are missing at random given the report day. Check whether cases without onsets differ, for example by delay, place or outcome. If they do, every method here is biased.
- **Delays changing over time.** The generative method estimates one delay for the whole vintage. If delays shorten as the response scales up, supply a delay or use a model with a time-varying delay.
- **Censoring and truncation.** If you fit your own parametric delay to pass as `delay`, fit it with double interval censoring and right truncation, for example with [primarycensored](https://primarycensored.epinowcast.org) or [epidist](https://epidist.epinowcast.org).
- **Noise.** EM back-projection has no smoothing. With small counts its daily output is noisy. Aggregate to weeks, or use a full model.
- **Recent days.** Onsets in the last weeks before the cut-off are incomplete under every method, because cases with those onsets are still being reported.

For production use, a model that treats missing onsets as part of the observation process is the better option, for example [epinowcast](https://package.epinowcast.org/articles/model.html#accounting-for-reported-cases-with-a-missing-reference-date).
